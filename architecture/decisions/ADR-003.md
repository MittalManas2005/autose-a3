# ADR-003: Role-specific hand-offs of full artifacts; the reviewer gets only issue, diff and repository

- **Status:** Accepted
- **Date:** 2026-11-22
- **Assignment decision:** D3 (hand-offs)
- **Decided by:** MittalManas2005, choosing from the options in `architecture/decision_briefs.md` (prepared with AI assistance)

## Context
Each agent needs enough information to do its job, but extra context costs tokens, can bias the agent, and for the reviewer would break the assignment's independence rule. The reviewer must see only the issue, the diff and the repository at the PR's latest commit.

The Design agent must read the target repository's `ARCHITECTURE.md`, which is kept in the private submission repository `autose-a3`. The fork's `GITHUB_TOKEN` "is limited to the repository that contains your workflow", so it cannot read `autose-a3`.

## Decision
Agents exchange **full, structured artifacts** (Markdown with YAML front matter), never LLM summaries and never conversation transcripts.

| Agent | Receives | Deliberately excluded |
|---|---|---|
| Requirements | issue title and body (as untrusted data), repository read-only | — |
| Design | issue, `spec.md`, `ARCHITECTURE.md`, repository | requirements agent's conversation |
| Implementer | `spec.md`, `design.md`, repository; on retry the failing-test excerpt; on rework the reviewer's findings | earlier agents' conversations |
| Tester | `spec.md` (acceptance criteria), repository with the change applied | implementer's reasoning, `design.md` |
| Reviewer | issue, diff (`git diff base...head`), repository at the PR head | `spec.md`, `design.md`, `test_report.md`, PR description, all conversations |
| Single agent (experiment E1 only) | issue, `ARCHITECTURE.md`, repository | — |

**How `ARCHITECTURE.md` reaches the Design agent:**
- a byte-identical copy is bundled with the agent code in the fork at `autose/context/ARCHITECTURE.md`;
- `autose-a3/ARCHITECTURE.md` stays the original;
- a sync script copies it, and a check compares the SHA-256 of both copies before each experiment batch;
- the Design prompt tells the agent to verify claims against the source and report discrepancies.

## Alternatives considered
| Alternative | Why not chosen |
|---|---|
| LLM-written summaries between stages | Cheaper context, but lossy, and errors compound across stages. Our artifacts are short. |
| Every agent sees every artifact | Simplest, but it biases later agents and breaks reviewer independence. |
| Read token for `autose-a3` used by one step | The token could also read the hidden tests, and a fine-grained token can't be limited to a single file. |
| Paste `ARCHITECTURE.md` into the prompt at build time | Works, but the file is less inspectable in the run and harder to keep in sync visibly. |

## Consequences
**Positive**
- Smaller, focused prompts.
- The reviewer's independence is enforced by what the review job downloads, not only by instructions.
- No credential in the fork can reach the hidden tests.

**Negative / risks**
- The Tester doesn't see the design, so it may test less of the internal edge cases. It works from the acceptance criteria only, by intent.
- The bundled `ARCHITECTURE.md` can drift from the original; the hash check detects that.
- The reviewer can still read files in the repository at the PR head, including the agent prompts under `autose/`. Those are prompts, not the implementer's reasoning, but this is a stated limitation.

## Evaluation
Experiment E1 compares this hand-off structure with a single context. The review job's logs show which files were downloaded, as evidence that no build artifacts reached it.
