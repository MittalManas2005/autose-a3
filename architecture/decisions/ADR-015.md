# ADR-015: Haiku for every role, including the reviewer (Sonnet kept as a selectable reviewer)

- **Status:** Accepted
- **Date:** 2026-11-22
- **Supersedes:** ADR-006
- **Assignment decision:** D6 (models)
- **Decided by:** MittalManas2005, after experiment E2 (option prepared with AI assistance). Both reviewer models are reported in the report as an ablation.

## Context
ADR-006 put the more capable model, Sonnet, in the reviewer role. Its reasoning: the reviewer is the last line of defence, and a *different* model reduces shared blind spots. It set its own test: "If Haiku catches as much at lower cost, this ADR is superseded." Experiment E2 (`experiment/variants.md`) fixed the decision rule before any run: "if Haiku catches the same seeded defects with no more false verdicts, supersede ADR-006 in favour of the cheaper model."

**E2 evidence** (all runs in `results/runs.md`; scoring with justifications in `results/e2_scoring.csv`):

| Measure | Sonnet reviewer | Haiku reviewer |
|---|---|---|
| Seeded defects caught (S2–S5), naming the planted defect | 4/4 | 4/4 |
| Correct PR (S1) approved | yes | yes |
| False approvals / false requests for changes | 0 / 0 | 0 / 0 |
| Extra true findings beyond the seeded defects | 0 | 1 major: the reference fix for issue 5 fails for labels containing `<` or `&` (verified on the branch); also 1 correct minor note on S1 |
| Real baseline PRs (#8, #9, #10, #12, #13) | 5 approved | 5 approved |
| The real gap in PR #12 (the `` [text][`x`] `` form) | missed | missed (neither model sees the maintainer's clarifying comment) |
| Commands run per seeded review (mean) | 2.0 | 7.0 |
| All tokens, 5 seeded reviews | 413 k | 1.03 M |
| List-price equivalent, 5 seeded reviews | $0.27 | $0.04 |

The rule is met. Haiku caught the same defects with no false verdicts. It used **more** tokens, because it probed more, but its usage is much lighter: about 6.5× less at list price. That is what the Pro plan's limits track.

## Decision
- **The default reviewer is Claude Haiku**, effort `medium`, the same model as the producing roles. The default changes in `config.ROLES["reviewer"]`, in the gate's defaults, and in the `workflow_dispatch` input `reviewer_model`.
- **Sonnet stays selectable** for any review (`reviewer_model=sonnet`), so both configurations can be re-run as an ablation.
- **The reviewer's independence still rests on structure**, not on model diversity: a separate job and context, restricted inputs, trusted code, no write tools, and an approval that needs transcript evidence of a passing test run (ADR-003, ADR-013, ADR-014).

## Alternatives considered
| Alternative | Why not chosen |
|---|---|
| Keep Sonnet (ADR-006 as it was) | It would override a rule fixed before the experiment, with no measured difference in catches. Sonnet stays available as an option and in the report's ablation. |
| Run both reviewers and require both to approve | Stronger, but doubles review usage for no measured gain on these PRs. A possible future step if the seeded set grows. |
| Choose by token count rather than usage | Sonnet would "win" on tokens (413 k vs 1.03 M), but tokens are not what limits a Pro plan. List-price usage is the closer measure of what each review costs. |

## Consequences
**Positive**
- Reviews cost about one sixth as much, so more review rounds and more seeded checks fit in the plan.
- Haiku's more exhaustive probing found one real defect that Sonnet missed.

**Negative / risks**
- **No model diversity** between writer and reviewer. They may share blind spots. E2 cannot rule this out: 5 seeded PRs, one review each, all in one repository.
- Neither model caught the PR #12 gap. That is an input problem (the reviewer doesn't see the maintainer's clarification), not a model problem, and is handled separately.
- Results hold for these model versions only.

## Evaluation
- **Reported as an ablation:** the Sonnet and Haiku columns above, for the seeded and the real PRs.
- **After this ADR,** new runs use the Haiku reviewer. Any later seeded PRs are reviewed with both models to watch for divergence.
