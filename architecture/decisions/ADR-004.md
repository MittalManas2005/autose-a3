# ADR-004: State in workflow artifacts and `run_state.json`; the PR branch holds only code and tests

- **Status:** Accepted
- **Date:** 2026-11-22
- **Assignment decision:** D4 (state)
- **Decided by:** MittalManas2005, choosing from the options in `architecture/decision_briefs.md` (prepared with AI assistance)

## Context
Stages run in different jobs (ADR-002) and sometimes in different runs. A run stopped with NEEDS_INPUT resumes after a maintainer's answer, and a failed job can be re-run. State must survive these boundaries. It must also be auditable by anyone, and must not leak the implementer's reasoning to the reviewer (ADR-003).

## Decision
**Within a run:**
- every stage writes its artifact (`spec.md`, `design.md`, `diff.patch`, `test_report.md`, `pr.md`, `review.md`);
- the orchestrator writes `run_state.json`: current stage, round, retries left, transitions taken, stop reason, base commit;
- per-call token counts go to `usage.json`;
- all are uploaded as **workflow artifacts** named `autose-issue<N>-r<round>-<stage>`.

**On the branch:**
- the PR branch `autose/issue-<N>` contains **only code and tests**; no AutoSE artifacts are committed;
- one PR per issue, reused on reruns and rework rounds (new commits on the same branch, so the reviewer always sees the latest commit).

**Across runs:**
- the report job keeps **one status comment** on the issue;
- the comment holds links to the run and a machine-readable marker with the run ID and state;
- a resume run (e.g. after NEEDS_INPUT) reads that marker and downloads the previous run's `spec.md` for the A1 skill's update mode.

**Restarts:**
- "Re-run failed jobs" reuses the artifacts of jobs that succeeded;
- branch push and PR creation are idempotent (find the existing branch/PR and update it).

## Alternatives considered
| Alternative | Why not chosen |
|---|---|
| Commit artifacts to the PR branch | Simple and durable, but the reviewer would read spec, design and test report through "the repository at the PR head", which breaks independence. |
| Actions cache | Can be evicted; not meant for audit data. |
| PR comments as the state store | Hard to parse reliably, and visible to the reviewer. |
| External store (database, gist) | An extra credential and service for no benefit. |

## Consequences
**Positive**
- Every run can be followed from its artifacts.
- The reviewer's view stays clean.
- Resume and re-run are possible.

**Negative / risks**
- Artifacts and logs expire after 90 days by default. Evidence is mirrored into `autose-a3/results/` for grading.
- Resume depends on the status comment's marker; if the marker is edited by hand, resume stops with an error instead of guessing.

## Evaluation
Re-run a failed job and check that it resumes from the right stage. Answer one NEEDS_INPUT run (issue 5) and check that update mode receives the previous `spec.md`.
