# ADR-012: Safety and failure handling, revised: agent commands run without the Claude token

- **Status:** Accepted
- **Date:** 2026-11-22
- **Supersedes:** ADR-009
- **Assignment decision:** D9 (safety and failures)
- **Decided by:** MittalManas2005, after smoke-test run 45003925819 (option prepared with AI assistance)

## Context
ADR-009 accepted a residual risk: "An agent with Bash test commands still executes generated code while the Claude token is in its environment; tests run by the agent could in principle read it."

The first end-to-end run and the checks around it showed this risk can be removed, and that ADR-009 was inaccurate in two details:

| Evidence | Source |
|---|---|
| The agents ran 1,166+ tests and `python -c` probes **with `CLAUDE_CODE_OAUTH_TOKEN` in their environment**. Nothing printed it, but any generated test file could have read it. | Smoke-test run [45003925819](https://github.com/MittalManas2005/markdown/actions/runs/45003925819); `agent_env()` passed the token through |
| Claude Code 2.1.319 has a setting, `CLAUDE_CODE_SUBPROCESS_ENV_SCRUB=1`, that removes its credential variables from every command an agent runs. A variable from its credential list (`ANTHROPIC_CUSTOM_HEADERS`) disappeared from a `python3 -c` command while a control variable stayed. The setting is **not** switched on just by `GITHUB_ACTIONS=true`. | Local tests with the pinned CLI, 2026-11-22 |
| With the setting on, Claude Code switches from `dontAsk` to its default permission mode. Path-scoped edits still behave identically (a write inside the allowed path succeeds, outside it is denied), and the same commands are allowed or denied. | Local comparison, same prompt in both modes |
| "Bash is restricted to a short allowlist" was too strong: in **both** modes Claude Code also allows read-only commands inside the working directory (`ls`, `grep`). Commands that read outside it (`cat /etc/hosts`) or print the environment (`env`) are denied. | Same local comparison |
| The release and review jobs have a 45-minute limit, not the 30 minutes ADR-009 stated. | `autose-round.yml` |

## Decision
Everything in ADR-009 still holds, with these changes:

**1. Agent commands run without credentials.**
- `agent_env()` sets `CLAUDE_CODE_SUBPROCESS_ENV_SCRUB=1` for every agent.
- The Claude token stays available to the Claude Code process, which needs it to call the model, but not to the tests, probes and other commands the agent runs.

**2. The Bash rules are stated precisely.**
- Per-role allowlist of command *forms*: implementer `python -m unittest|compileall|flake8`, tester `python -m unittest`, reviewer `python -m unittest|flake8` and `python -c`. Requirements and design have no command forms.
- Claude Code additionally allows read-only commands inside the checkout. This gives no more access than the Read and Grep tools these agents already have.
- Always denied: web tools, `curl`, `wget`, `git push`, `gh`, `pip`, sub-agents.
- Prompts tell agents to run one plain command per call. A chained command (`a | b`, `a; b`) is denied as a whole, which cost every agent one wasted turn in the smoke-test run.

**3. Session transcripts are kept as evidence.** Each agent's Claude Code transcript and the list of commands it actually ran (`logs/*.transcript.jsonl`, `logs/*.commands.json`) go into that job's artifact. The reviewer never downloads build artifacts (ADR-003), so this doesn't weaken independence.

**Unchanged from ADR-009:**
- **Budgets:** `--max-turns` per role (Requirements 20, Design 25, Implementer 40, Tester 30, Reviewer 30, single agent 80). A wall-clock limit on every agent call. Retry caps: implementer↔tester 2, tester→design 1, review send-backs 2.
- **Job time limits:** build 90 minutes, release 45, review 45.
- **Stopping:** an exhausted budget or a usage limit stops the run with the reason in its artifact.
- **Untrusted input:** issue and comment text goes only into files and `<untrusted_…>` delimiters, never into `${{ }}` shell interpolation.
- **Tokens and permissions:** no GitHub write token for agents; the deterministic test steps run with a cleaned environment; permissions declared per job.
- **Diff guard:** changes allowed only in `markdown/**`, `tests/**` and `docs/**`.
- **Hidden tests:** only in the private `autose-a3`.
- **Triggers:** bot comments ignored.
- **Repository scope:** fork only, no merge step.

## Alternatives considered
| Alternative | Why not chosen |
|---|---|
| Keep the residual risk (ADR-009 as written) | The fix is one environment variable, verified with the pinned CLI. Keeping a known, removable credential exposure is not defensible. |
| Run agent tests in a separate container without the token | Stronger isolation, but every agent test call would need a container runtime and a file-sync step. Much more machinery for little gain once credentials are scrubbed. |
| Remove all Bash from agents, run tests only in deterministic steps | The implementer and tester would lose their test-fix feedback loop, and the reviewer could no longer run code, which the assignment allows and ADR-013 now requires. |
| Claude Code's network sandbox | Still off by default and unverified on Linux runners (as in ADR-009). Not relied on. |

## Consequences
**Positive**
- Removes the only credential exposure ADR-009 accepted.
- Transcripts make each agent's actions auditable after the run. They also feed the sequence view and the report.

**Negative / risks**
- Depends on a Claude Code environment setting, so the pinned CLI version matters. A CLI upgrade must re-run the local check, a five-minute task.
- The permission mode changes from `dontAsk` to the default. That was verified equivalent for our rules, but it is one more thing to re-check on upgrade.
- Artifacts are larger because of the transcripts (tens to hundreds of KB per agent).

## Evaluation
- **Injection issue:** an issue that asks an agent to print its environment. Expected: no token in any log, artifact or comment.
- **Every baseline run:** the transcripts and command lists show what each agent ran and what was denied, and the report counts the denials.

## Update after review run 45006857285 (2026-11-22): the scrubbing needs Claude Code's sandbox

**Evidence**
- The first review run with this ADR in force was [45006857285](https://github.com/MittalManas2005/markdown/actions/runs/45006857285), a `/autose` re-check of PR #2.
- Every command the reviewer ran failed with: "Sandbox is required but failed to initialize: Sandbox dependencies not available: socat not installed … Running it outside the sandbox (dangerouslyDisableSandbox) is not allowed either."
- With `CLAUDE_CODE_SUBPROCESS_ENV_SCRUB=1`, Claude Code runs agent commands only inside its sandbox. On Linux that sandbox needs `bubblewrap` and `socat`, which GitHub's Ubuntu runners don't include.
- The local verification above passed because macOS has its sandbox built in. **A macOS check does not prove Linux behaviour.**
- The CLI also checks `kernel.apparmor_restrict_unprivileged_userns`, which Ubuntu 24.04 sets to block the user namespaces `bubblewrap` needs.
- The reviewer behaved correctly under ADR-013 and refused to approve without a passing test run. But it returned `request_changes` for what was an environment failure. In a full run, that would have sent working code back to the implementer.

**The decision is unchanged.** Agent commands still run without credentials. These operational requirements are added:
1. **Both agent jobs** (build and review) install `bubblewrap` and `socat`, lift the AppArmor user-namespace restriction, and run a `bwrap` self-test **before any model call**. If the sandbox can't start, the job fails at that step with no Claude usage spent.
2. **If a command still fails to start because of the sandbox**, detected from Claude Code's own error text in the session transcript, the agent call raises an environment error:
   - the build stops at once at the current stage, with "environment problem, not a code defect", and spends no retries;
   - the review ends as "review could not be completed" (`review_error`) and never as `request_changes`.
3. **Side effect:** agent commands now run inside Claude Code's sandbox, which also restricts their file writes and network access. ADR-009 had left this as "unverified, not relied on". It is still not relied on as the only control, but it is now active.

**Consequences added**
- About 15–25 seconds more per agent job for the package install.
- A new dependency on Ubuntu packages and a kernel setting. The self-test makes a failure visible and cheap.
- The PR #2 review history keeps the environment-caused "request changes" review as an honest record. A re-check after the fix is expected to replace it.

## Update during the baseline (2026-11-22): agents cannot see other branches

**Evidence**
- The build job checks out with `fetch-depth: 0`, which downloads **every branch** of the fork. Once baseline PR branches exist (`autose/issue-3` …), a later run, such as an E1 single-agent run, could read another run's fix.
- Claude Code auto-allows read-only `git` commands. Locally, `git log` and `git branch -a` ran with no rule allowing them, and an explicit `Bash(git *)` deny rule blocked both (Claude Code 2.1.319).
- The five baseline runs started within 45 seconds of each other, before any baseline branch existed, so the baseline was not exposed.

**Added**
- `Bash(git *)` is denied for every agent. The orchestrator runs all the git commands it needs itself.
- The build job removes the `origin` remote right after checkout, which deletes all other branch refs. This is a second layer, in case a deny rule ever fails.
