# ADR-009: Safety and failure handling: budgets, timeouts, untrusted input, least privilege

- **Status:** Superseded by ADR-012 (2026-11-22, after smoke-test run 45003925819). Kept unchanged below as the original record.
- **Date:** 2026-11-22
- **Assignment decision:** D9 (safety and failures)
- **Decided by:** MittalManas2005, choosing from the options in `architecture/decision_briefs.md` (prepared with AI assistance)

## Context
- **Anyone can write an issue** on the public fork, so issue and comment text may contain prompt injection, and code an agent writes may be malicious.
- **GitHub-hosted runners have internet access by default.**
- **The Claude Pro plan has usage limits** that can interrupt a run.
- **Stages can loop or stall.**
- **The hidden tests** in the private `autose-a3` must stay unreachable from the agents.

## Decision
**Budgets and timeouts**
- `--max-turns` per role: Requirements 20, Design 25, Implementer 40, Tester 30, Reviewer 30, single agent 80. These are starting values, recorded in configuration and tuned only with evidence.
- `timeout-minutes` per job: build 90, release 30, review 30.
- Every agent call also has a wall-clock limit.
- Retry caps: implementer↔tester 2, tester→design 1, review send-backs 2 (ADR-002).
- **When a budget runs out**, or the Pro plan hits a usage limit, the stage writes the reason into its artifact and the run stops. It never silently continues.

**Untrusted input**
- Issue and comment text is fetched through the API into files. It is never interpolated with `${{ }}` into shell scripts.
- In prompts it is wrapped in `<untrusted_issue>` delimiters and treated as data (adapted A1 skill, rule R4; same instruction for all roles).

**Least privilege**
- Agents get **no GitHub write token** (ADR-005). The Claude token is present only in agent steps.
- Bash is restricted to a short allowlist of compile and test commands. There are no web tools.
- The full test suite runs in a deterministic step with a cleaned environment (no tokens).
- Job permissions are declared per job, and the repository default token is read-only.
- The **diff guard** blocks changes outside `markdown/**`, `tests/**`, `docs/**`, including `.github/**`, `autose/**`, `tox.ini` and packaging files.

**Hidden tests**
- They live only in the private `autose-a3`.
- The fork's `GITHUB_TOKEN` is limited to the fork, and no token with access to `autose-a3` exists in the fork.

**Bot loops**
- Comment triggers ignore comments by bots and require an exact `/autose` prefix (ADR-010).

**Fork only, never merge**
- The workflow calls the GitHub API only for its own repository (`github.repository`), and has no merge step.
- The App's permissions don't allow administration.

## Alternatives considered
| Alternative | Why not chosen |
|---|---|
| Rely on prompt instructions alone against injection | Instructions can be overridden by injected text. Permissions and post-hoc guards cannot. |
| Network sandbox for agent Bash | Claude Code's sandbox exists but is off by default and unverified on Linux runners. It can be added later; we don't rely on it. |
| No budgets, retry until green | Unbounded cost on a usage-limited plan, and possible endless loops. |

## Consequences
**Positive**
- Several independent layers stand between a malicious issue and the repository or secrets.
- Every stop has a recorded reason.

**Negative / risks**
- An agent with Bash test commands still executes generated code while the Claude token is in its environment; tests run by the agent could in principle read it. This is mitigated by the Bash allowlist and short-lived runs, and stated as a residual risk.
- Fixed turn limits may stop legitimate long tasks; that shows up in the results.

## Evaluation
- One adversarial injection issue, in addition to the five: it tries to make an agent change CI files and reveal secrets. Expected: blocked, with the attempt recorded.
- Budget-exhaustion cases are reported from `run_state.json`.
