# Independent reviewer findings (address every item)

The core fix works for ordinary code labels, but it does not handle code labels containing HTML-special characters (< > &), and the PR includes an unrelated CI change that disables a changelog gate. Both need fixing before merge.

- [major] markdown/inlinepatterns.py:1240 _label_source() rebuilds the inline-code text from the stashed code element's .text, which is already HTML-escaped (code_escape runs when the span is stashed). For labels containing <, > or & the rebuilt id never matches the raw reference definition, so the link is still dropped and the brackets show as literal text. This is the same symptom the issue reports, left unfixed for a common class of code labels such as List<int> or a&&b. The rebuilt text should be unescaped (for example with html.unescape) before lookup, and tests should cover these characters. — evidence: python -c 'import markdown; print(markdown.markdown("[`a<b`]\n\n[`a<b`]: https://example.com"))' outputs <p>[<code>a&lt;b</code>]</p>; expected <p><a href="https://example.com"><code>a&lt;b</code></a></p>. The same happens with [`a&b`], which outputs <p>[<code>a&amp;b</code>]</p>. The new tests use only plain identifiers, so they do not catch this.
- [major] .github/workflows/changelog-enforcer.yml:9 The diff adds continue-on-error: true to the changelog-enforcer CI step. This is unrelated to the issue, changes a CI file (which the repository rules forbid), and turns a required check into a non-blocking one. — evidence: diff.patch lines 5-10: '+      # Do not block pull requests on changelog formatting.' and '+      continue-on-error: true' added to the Ensure Changelog Entry Made step. Revert this hunk.
