The notoc exclusion works as the issue describes: the class is honoured, the heading keeps its id and rendering, and it is left out of both the TOC and md.toc_tokens. However, the PR also changes how every explicitly set attr_list id is handled, which breaks existing custom anchors and is outside the issue. It also deletes an existing regression test that would have caught this. Request changes.

- [major] markdown/extensions/toc.py:406 The new `else` branch rewrites every pre-set id from attr_list through slugify, not only ids on notoc headings. Explicit ids are no longer kept as written, so existing anchors and links break, and headings with other classes no longer behave as before. The issue asks that the heading's id be rendered normally and that other headings behave exactly as today. — evidence: Probe on PR head: `# Intro { #my_custom.id }` gives `<h1 id="my_customid">`. `## Sub {: #Some_Id }` plus `[link](#Some_Id)` gives `<h2 id="some_id">`, and the link still points at `#Some_Id` (dead anchor). Base code only set an id when none existed, so these ids were emitted verbatim.
- [major] tests/test_syntax/extensions/test_toc.py:1079 The PR deletes the existing test `test_escaped_char_in_attr_list`, which asserts that an attr_list id `\*Foo\*` is emitted and linked as `*Foo*`. Deleting it hides the regression from the id change above and makes the green suite misleading. The test was not weakened or replaced; it was removed without justification. — evidence: The diff removes lines 73-97 of tests/test_syntax/extensions/test_toc.py (expected `<h1 id="*Foo*">` and `href="#*Foo*"`). With the new slugify branch that id is normalised, so the original expectation no longer holds. The suite passes only because the test is gone.
